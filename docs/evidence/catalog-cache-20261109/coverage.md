# 证券目录持久行情缓存修复

2026-11-09，正式本机8765验收。

- 根因：基础目录5223条，仅91条已有报价；后台原来只覆盖自选及最近访问。新增独立目录报价worker，仅保存market_snapshot，不物化全目录security、不登记最近访问、不补全市场历史、不触发算法或交易。
- 缓存优先：GET仅读取本地快照并登记有界当前页需求；单批最多50只、单线程批间等待0.5秒，当前页按设置30秒到期，其他股票至少60秒到期，休市至少300秒。到期表示进入待更新队列，全目录轮换完成耗时受股票数量、限流和上游网络影响，并非全市场每30秒同时更新。关闭自动更新不发下一批请求。
- 持久化：实际从91条自动补至5223/5223；服务再次重启后仍完整保留。首两页及offset=5000页各100只均有缓存，未打开的股票也取得报价。来源时间为2026-11-09收盘后报价；缓存覆盖完整不代表所有可选字段均有值。
- 隔离：报价源失败保留成功快照并退避，重复GET不绕过退避。单只缺失或身份/数值无效时隔离该证券后继续其余批次，不补零；旧源时间快照不得覆盖较新报价。
- 统一：目录、搜索、自选共用public_quote，包含TTM旧映射修正、源时间as_of、缓存过期标记与单位口径；没有持续推送或交易所实时授权声明。
- 性能：全局响应元信息改为索引SQL聚合，避免反序列化全市场盘口。线程采样进一步定位到原security()在已有快照时仍读多年日线，多个全局轮询占用SQLite锁；已跳过无必要历史读取。当前页快照使用一次批量读取，避免逐行竞争锁。
