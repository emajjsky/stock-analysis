# 0.3.2旧页面缓存升级验收

2026-11-15。0.3.1上一轮仅使用新建Chromium配置目录测试，漏掉真实用户配置中的旧HTML缓存。用户截图中的“运行一次”“选择算法发现候选”和没有进度，来自缓存中的0.3.0页面。

## 根因复现

使用用户原有默认配置启动0.3.1，实际主进程和服务均为0.3.1，页面却载入`index-CVR4DFXH.js`，标题为“让每个机会，都有计算依据。”，按钮仍是“运行一次”。旧页面调用同步`/lab/run`，不会创建独立`lab_job`任务。此现象与干净目录加载新版页面不同。

最初只查看旧开发服务端口不足以确认根因；最终通过实际客户端的页面资产和服务版本对照，确认是默认用户配置中的页面HTTP缓存。

## 修复与验收

- 启动时只清HTTP缓存，保留用户配置、Cookie和数据库；入口带版本并禁止HTML缓存，哈希静态资源仍可缓存。
- 核对服务版本与进度接口，拒绝复用版本不符或没有任务接口的旧服务，不只检查目录接口存在。
- 全局筛查进度条跨页面显示并吸附在视口顶部，包含已计算/总数、百分比、已满足数量、当前股票。断网保留上次进度并提示重连。
- `scripts/verify_client_upgrade.cjs`先在同一配置目录缓存旧页面，验证重复访问确实命中旧缓存；随后启动真实0.3.2发行包，核对缓存更新、本地偏好保留、全量筛查进度递增、滚动可见、切设置/返回/刷新同一任务及完成结果。
- `checks.json`记录全量5,223只计算、单次提交、336只满足、2只指标不足，无页面异常且退出后自有服务关闭。截图展示运行中滚动、设置页、返回恢复及完成结果。
- 另用原有默认用户配置与默认8766端口复验，结果见`existing-profile-check.json`。此步骤只运行确定性筛查，不启用模型或交易，原有业务记录保留。
