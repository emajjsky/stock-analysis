# A 股算法功能与开源方案调研

调研日期：2026-11-14。目的是解释用户操作、自动计算、页面展示和配置边界，为“王炸”的下一轮设计提供依据。本轮没有修改应用代码、运行开源交易软件、接入模型或启动定时分析。

## 1. 调研结论

建议先设计“选股—监测—验证”的使用流程，再选择算法实现。首版面向普通用户提供中文模板和合理默认值，代码、模型训练与大批参数留给开发者和高级研究。

开源项目的参考价值应分开看：

- go-stock：条件选股、结果表、收藏策略、独立监测池与信号流水等产品交互。
- daily_stock_analysis：分析任务、进度、历史报告、定时运行与配置；其纯规则 ETF 轮动可研究算法与服务分离。
- VeighNa/vn.py：策略实例的创建、初始化、启动、停止，以及图形化回测和参数优化。
- Qlib：股票池、特征、训练/验证/测试切分、预测、组合与回测的研究流程。
- CZSC：K 线结构、信号函数、事件组合和多周期分析。
- RQAlpha：数据事件驱动策略、费用和撮合等 A 股回测设计；存在非商业使用限制。

以上是静态源码与文档审阅，未验证安装可用性、接口长期稳定性或策略收益。

## 2. “算法”在产品里至少分四层

| 层次 | 输入 | 输出 | 常见触发 | 用户操作 |
|---|---|---|---|---|
| 指标 | 某股行情、K 线 | MA、MACD、成交量比值等 | 对应数据更新 | 选择显示哪些指标，可沿用默认参数 |
| 选股 | 一组股票、完整历史、筛选条件 | 候选名单、排序、入选原因 | 手动，或数据到齐后的盘后任务 | 选择模板、范围，可开启盘后自动运行 |
| 信号监测 | 已启用的监测池、规则、对应周期数据 | 新触发事件与提醒 | 报价或新完成 K 线到达 | 明确加入监测、选择周期和提醒 |
| 交易策略 | 信号、资金、仓位、进出场、费用、可成交性 | 仓位与订单计划、回测或模拟结果 | 回测、模拟或获授权执行流程 | 额外设置账户与风险约束 |

Agent 是另一条分析链：读取候选/信号及证据，形成解释和研究意见。规则计算通常无需大模型；AI 报告不天然构成可回测的交易策略。

## 3. 自动和实时怎样区分

### 行情刷新

行情服务按来源能力更新报价，页面读缓存并标明源时间。源更新、后台取数和页面刷新是三个不同时间点。轮询不能宣称逐笔实时。

### 盘后选股

日线模板默认只使用完整日线。任务应在真实交易日、当日日线到齐并通过质量检查后运行，记录数据截止日期。触发可设盘后某个时间点，但时间到了不代表数据完整；需提供等待、缺失剔除、失败、重试和覆盖统计。

盘中也能重算日线算法，但只用已完成日线时通常仍得到前一交易日的结果。若引入当天未完成数据，应另标“盘中预览”，收盘再确认。

### 盘中监测

实时价格阈值可在新报价到达时检查；5 分钟策略通常在新完成 5 分钟 K 线到达时确认。每 30 秒扫描并不意味着每 30 秒都有一条新 K 线。日线规则即使每分钟检查，也不会因此获得分钟级策略能力。

监测只覆盖用户明确启用的池。连续满足条件时应按规则识别新事件、去重并遵守提醒冷却，避免重复弹窗。旧行情触发的历史事件不能冒充新信号。

### Agent 分析

先提供手动复核。后续可单独开启“新有效信号自动复核”，配置模型、次数/预算和时效。页面轮询、切换股票、行情刷新不应顺便请求模型。失败与证据不足应有明确状态。

### 回测

选择历史区间和完整策略后手动运行，必要时配置研究任务。每次结果绑定参数、算法版本、数据快照与成本假设，不能随实时价格刷新被静默改写。

## 4. 建议的用户使用流程

1. 在“选股”选择“趋势走强”或“放量突破”等内置模板。
2. 选择股票范围，首版默认“我的自选”或用户显式选定的研究池。
3. 使用默认规则，点击“运行一次”；高级参数折叠。
4. 查看候选表：股票、命中条件、关键指标值、数据截止日、运行时间、风险和缺失项。
5. 点击一行，打开个股图表并标记相应条件；允许单独加入监测。
6. 在“监测”明确启用某条规则和提醒；持续查看信号事件记录。
7. 按需点击 Agent 复核；在“验证”检查规则的历史样本和完整策略的回测结果。

“加入自选”和“加入监测”分开；“保存参数”和“启用自动运行”分开。

## 5. 前端建议

算法入口可包含三个页签，Agent 暂时从候选或信号进入：

- **选股**：模板选择、研究池、立即运行、盘后自动开关、数据覆盖、结果表、运行记录。
- **监测**：启用状态、证券池、规则与周期、最近数据时间、检查时间、信号确认时间、提醒记录。
- **验证**：规则说明、历史区间、成熟事件样本；完整回测开放后再展示资金曲线、回撤、基准、交易明细与成本。

模板详情应有中文条件清单。例如示意“放量突破”：今日完成日线收盘价高于此前 20 个交易日最高价，今日成交量至少为此前 20 日平均成交量的 1.5 倍。这里的“此前”明确排除当天，避免阈值含糊。参数为教学示例，未验证有效性。

用户通常只需选择模板、范围、自动运行方式和提醒方式。均线周期、突破窗口、量能阈值等放入高级设置；数据源凭据与模型凭据放在全局设置，不重复出现在每条规则里。

## 7. 王炸现状与实施依赖

本次检查 backend/app.py、backend/agent_review.py 及 DiscoverView、SignalsView、ValidationView、SettingsView：

- 已注册两套选股排序与两套观察信号；已有信号复核与模型调用协议。
- 选股运行读取 Store.security 与已保存 bars，历史不足会跳过。行情目录/报价缓存不等于算法已经拥有全市场完整历史。
- 当前指标图表的数据口径与原始策略输入分层；不能直接把图表前复权开关视为算法口径已同步切换。
- 现有验证页明确只交付成熟信号后验统计，资金策略回测尚未开放。
- 原有行情自动刷新、算法自动监测和 Agent 权限边界继续保留。

建议实施次序：

1. 先明确一个模板的输入、输出、研究池、完整日线口径和可操作界面。
2. 提供数据覆盖检查、运行记录和每条入选原因；首版先以自选/指定池运行。
3. 增加完整日线到齐后的盘后任务，并补交易日历、失败状态和去重。
4. 再扩展规则和历史验证，设计持有期、退出、交易成本及基准；回测与选股分开。
5. 最后扩展分钟监测和真实 Agent 联调；分钟规则必须先有可靠历史与实时分钟数据。
